⚠️
Nguyên tắc bắt buộc khi xây Data Mart
✕Không đọc thẳng từ Data Lake — luôn build qua DWH, tránh query raw JSON tốn kém và không nhất quán
✕Không để Claude query DWH trực tiếp — phải qua data mart đã pre-join, đảm bảo latency < 3 giây
✕Không bỏ Row-level Security — mỗi mart phải có RLS theo đúng đối tượng
✕Không rebuild toàn bộ — chỉ incremental refresh, tránh vượt budget BigQuery

BƯỚC 6 — Trả kết quả cho người dùng
Claude nhận JSON từ BigQuery → tổng hợp thành ngôn ngữ tự nhiên tiếng Việt → kèm số liệu cụ thể, cảnh báo nếu phát hiện vấn đề, gợi ý hành động tiếp theo. Latency toàn bộ: 3–5 giây.
Lý doTại sao Claude kết nối Data Mart thay vì Data Warehouse?
✕ Nếu Claude query thẳng Data Warehouse
⚠Chậm: DWH chứa hàng triệu raw records — mỗi query phải join nhiều bảng, latency 10–30 giây
⚠Tốn kém: BigQuery tính tiền theo dữ liệu scan — query DWH lớn có thể vượt budget
⚠Rủi ro bảo mật: DWH chứa mọi thứ — khó kiểm soát Claude xem gì, ai được xem gì
⚠Dễ sai: Claude phải tự join nhiều bảng → có thể sinh SQL sai logic nghiệp vụ
✓ Khi Claude query qua Data Mart
✓Nhanh: Mart đã pre-aggregated, pre-joined — query đơn giản, latency < 3 giây
✓Tiết kiệm: Mart nhỏ hơn DWH 10–50 lần — chi phí scan thấp, nằm trong budget
✓Kiểm soát bảo mật: Mỗi mart có RLS riêng — quản đốc chỉ thấy line mình, lãnh đạo thấy tất cả
✓Chính xác hơn: Logic join và tính toán đã định nghĩa sẵn trong mart — Claude chỉ cần SELECT
Ví dụ thực tế: Câu hỏi "Line SMT-03 hôm nay OEE bao nhiêu, nguyên nhân dừng chuyền chính là gì?"
Query vào mart_production (đã pre-join WO + downtime + IoT, đã lọc theo RLS) → 0.3MB data scan → < 2 giây
Nếu query DWH raw → phải join fact_production × dim_equipment × iot_alarm_log × dim_shift → 2GB+ data scan → 15–30 giây + tốn ~$0.01 mỗi query
